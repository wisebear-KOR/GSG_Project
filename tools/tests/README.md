# 결정론·퍼징·해석·밸런스 검사

웹판 규칙 엔진을 봇으로 수백~수만 판 돌려 불변식을 확인하고(결정론·퍼징), 석판 해석기가 문장을 알아듣는지 보고(회귀 시험), 규칙 밸런스를 잰다(벤치마크). 모두 빌드 없이 `node`로 돈다. 퍼징이 무엇을 확인하는지는 [04 구조 §5.2](../../docs/spec/04-architecture.md)에 있다.

## 결정론·퍼징

| 명령 | 하는 일 |
|---|---|
| `node tools/tests/det.mjs` | 같은 시드면 사건 덱 순서가 플레이와 무관한지(율법 카드는 쉬움에서만 — 보통·어려움은 지난 계시를 듣고 맞서는 카드를 고르므로 계시에 따라 바뀌는 것이 설계다, [02 §4.3](../../docs/spec/02-rules.md#43-이번-장-카드-고르기)), 저장·복원 뒤에도 결과가 같은지 |
| `node tools/tests/fuzz.mjs [판 수=600] [random\|smart] [시드]` | 무작위/영리한 봇으로 판을 돌리며 불변식 위반(음수 자원, `undefined`/`NaN` 문구, 저장·복원 차이 등)을 모은다. 결과는 `result-<정책>.json` (커밋하지 않는다) |
| `node tools/tests/stats.mjs tools/tests/result-smart.json` | 퍼징 결과의 난이도·맵별 승률 표 |
| `node tools/tests/edge.mjs` | 경계 사례 모음 |
| `node tools/tests/heresy.mjs` | 신앙 바닥(이단) 흐름 |

`lib.mjs`는 `main.js`에 있는 한 장 진행 규칙(말한 기적, 침묵, 청원 은총, 기본 노동에 계시의 교리 넘기기, 계명 새긴 뒤 다시 채우기 등)을 복제해 두었다(`doSpeak`/`doAccept`). `main.js`의 해당 부분을 고치면 여기도 맞춰야 한다. 다른 점 하나: `doSpeak`의 `reinterpret`는 석판 해석에도 다시 해석을 허용한다(화면은 석판 모드(`aiMode !== 'llm'`)면 단추를 숨긴다 — `e68a240`부터 해석 출처가 아니라 모드로 가른다).

`fuzz.mjs`의 `winner-before-resolve` 보고는 **번개가 아닌** 기적이 말하기 단계에서 판을 끝냈을 때만 나온다. 번개로 끝나는 판(마지막 신도를 쓰러뜨림 → `448f553`부터는 남은 자로 수도가 흔들려 점령)은 화면이 받는 정상 경로라 세지 않는다.

`extinct-no-remnant`(`fuzz.mjs:176`)는 `448f553`의 남은 자 규칙을 검사한다: 튜토리얼이 아니고 판이 이어지면 장 끝에 어느 쪽(플레이어·율법파)도 신도 0으로 남아 있으면 안 된다 — 장 중간에 0이 되어도 그 장의 승패 판정에서 수도가 흔들리고 한 명이 돌아오는 것이 정상이다. `e68a240`에서 예전 검사 `enemy-extinct-no-win`(율법파 인구가 장 중간에 0이 되면 승부가 나야 함, 남은 자 규칙 뒤로 거짓 경보)을 이것으로 바꿨다.

## 석판 해석기 회귀 시험

| 명령 | 하는 일 |
|---|---|
| `node tools/tests/tablet-cases.mjs [--all]` | 새 플레이어가 쓸 법한 문장 **254개**(`1b582ee`의 253개 + `e68a240`의 "~지 말고"가 둘인 문장)를 석판 해석기(`interpretWithTablet`)에 넣어 기대한 행동이 나오는지 본다. 틀린 문장만 찍고(`--all`이면 전부 `O/X | 문장 | 나온 행동 | 해석문`), 끝에 `석판 이해: n/254 (%)` |

- 상태: 튜토리얼 3×3 1장(율법파 마을이 바로 옆이라 선교·공격 대상이 있다)에 목재·돌·식량을 6씩 준다.
- 판정: 문장마다 `[문장, want, avoid]`. `want`의 행동 종류(`gather:food`… `build:village`… `pray`·`explore`·`preach`·`attack`, 아무 채집이면 `gather:any`, 금지는 `forbid:<종류>`)가 모두 나오고, `avoid`의 종류가 명령에 없으면 성공.
- 묶음 주석에 각 묶음의 **튜닝 전 첫 측정**이 남아 있다: 묶음 3 67%, 묶음 4 77%, 묶음 5(은유 섞음) 68%, 묶음 6(어휘를 보지 않은 에이전트가 씀) 90%. 평가(`docs/EVALUATION-2026-09-30.md`)의 자연 문장 시험은 41%였다. 지금 254개가 모두 통과하는 것은 이 문장들에 맞춰 사전을 고친 결과이므로, 새 문장의 이해율은 첫 측정값 쪽으로 읽는다. 자세한 것은 [05 해석기](../../docs/spec/05-interpreter.md).
- 사전(`kw.tablet.*`)을 고치면 이 시험을 돌리고, 골든(`node tools/golden.mjs`)이 바뀌는지 본다.

## 밸런스 벤치마크

| 명령 | 하는 일 |
|---|---|
| `node tools/tests/bench.mjs [quick\|full] [이름]` | 정해진 정책·맵·난이도 조합을 CPU 수 − 1개의 작업자(`bench-worker.mjs`)로 병렬로 돌리고 핵심 지표를 마크다운 표로 찍는다. 원자료는 `bench-<이름>.json`(이름 기본값 = 모드, 커밋하지 않는다 — `.gitignore`) |
| `node tools/tests/par.mjs <jobs.json> <out.jsonl> [작업자=15]` | 범용 병렬 실행기: `jobs.json`의 `[{cfg, pol, botSeed, opts?}]`마다 `sim.mjs`의 `runGame`을 돌려 한 줄씩 `{…job, res, err}`를 JSONL로 쓴다. 벤치 표가 다루지 않는 조합을 따로 잴 때 |

**`bench.mjs`의 조합**

| | quick | full |
|---|---|---|
| 맵 | 5×5, 7×7 | 4×4~7×7 |
| 난이도 × 판 | 보통·어려움 × 첫 판·두 번째 판 | 같음 |
| 고정 스크립트 `fix:temple` `fix:expand` `fix:combo` `fix:warcombo` `fix:preach` `fix:war` | 조합마다 50판 | 120판 |
| 영리한 봇 `smart` `planner` `smartcath` `warplan` | 24판 | 60판 |
| `randcmd` (그럴듯한 명령을 아무렇게나) | 50판 | 120판 |

찍는 표: 정책 × 조합별 승률, smart 판의 긴장 지표(최종 차 15점 이상 대차·3점 이내 접전 비율, 역전, 중반 8점 이상 선두 유지, 평균 길이, 끝난 방식), 계시가 정한 행동 비중(정책별 계시 / 교리를 따른 자동(`heeded`) / 그 밖의 자동), 율법파 교전(smart 상대, 난이도별: 공격 0회 판 비율, 판당 공격·수도 타격·마을 빼앗음·선교로 넘겨받음). 파일 머리의 목표치(평가 2026-09-30): 한 줄 스크립트 승률 < 50%, 공격 0회 판 < 20%(보통), 대차 < 30%, 역전 25~35%.

**`sim.mjs`** — 벤치·병렬 실행기가 쓰는 측정기(명령 줄 없음). `lib.mjs`의 한 장 진행으로 판을 끝까지 두고(`runGame(cfg, 정책, botSeed, opts)`), 승패·장별 승점(`h`)·양쪽 공격·선교·수도 타격·막힘·행동 종류·계시/자동/헤아린 행동 수·음수 자원·석판 최대치·분노 등을 모은다. `opts`: `dice`(주사위 시드 바꾸기), `deckShuffle`(덱만 다시 섞기), `textSpace`(석판으로 표현할 수 있는 계획 수 재기), `recordSmart`.

| 정책 | 하는 일 |
|---|---|
| `fix:<이름>` / `fixm:<이름>` | 매 장 같은 한 줄(`FIXED` 표: `pray` `preach` `war` `food` `expand` `temple` `wall` `explore` `expstone` `builder` `warpreach` `peacepray` `combo` `warcombo`, `silence`는 침묵). `fixm`은 기적도 쓴다 |
| `random` | 계시 목록(`REVELATIONS`, 이상한 글 포함)에서 아무거나, 기적·다시 해석·예언 봉인도 무작위 |
| `randcmd` | 그럴듯한 명령(`SMART_REVS`)에서 아무거나, 기적 없음 |
| `smart` | 후보 계시(`SMART_REVS`)마다 한 장 앞을 두 번씩 굴려(주사위 시드만 바꿔) 승점 차·자원으로 가장 좋은 것을 고른다. 기적은 간단한 규칙(`smartMiracle`) |
| `smart4`, `smartnomir` | smart에서 주사위 표본 4번 / 기적 없음 |
| `planner` | 숙련자 대용: 절 12개에서 한 장에 최대 세 절을 탐욕적으로 골라 한 문장으로 잇는다 |
| `warplan` | 정복 지향: 율법파 수도를 칠 수 있고 승률 45% 이상이면 "율법파의 수도를 쳐라, 성벽을 쌓아 지켜라", 아니면 planner |
| `smartcath` | smart + 사람 규칙 하나: 신전·대성당을 지을 수 있으면 늘 "신전을 높이 세우라" (대성당 거북이 전략 측정용) |
| `rollout` | 후보마다 싼 정책으로 판 끝까지 몇 번 굴려 고른다 (느리다) |

`afab303`의 재조정(원정·결집·굳은 율법·메아리·대성당 조건)과 `448f553`의 남은 자는 이 벤치로 전후를 쟀다 — 수치는 각 커밋 기록과 [02 §4.9·§10·§15.2](../../docs/spec/02-rules.md#49-율법파의-반격--원정칼대체-마을결집퇴각굳은-율법).
