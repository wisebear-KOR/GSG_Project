# 해석기 재설계 — 결정형 모델(Kev)로 (2026-10-06, 진행 중)

재설계 세 요소 가운데 2번(해석을 결정형 AI로)과 3번(해석문 쓰는 방식)의 논의 상태를 남긴다.
여기서 멈췄다: **질문 구성(1단계 질문의 꼴)을 정하기 전에, ONNX로 변환한 Kev가 브라우저에서 얼마나 빠르고 정확한지부터 확인하기로 했다.**

## 1. 정한 것

| # | 정한 것 | 근거·메모 |
|---|---|---|
| I1 | **해석은 결정형 모델 Kev**로 한다 | 사용자 결정. 의견으로는 생성형을 권했다 — 은유·문맥은 생성형의 몫이고 해석문에 생성이 필요하다. 해석문을 문장 틀로 쓰기로 하면서 결정형이 맞게 되었다 |
| I2 | **해석문은 문장 틀로** 쓴다 (3번) | 사용자 결정. 고른 일·칸·금지·성격·확신도를 틀에 넣는다 |
| I3 | **먼저 Kev-0.8B로 시험**한다 | 4B는 브라우저 다운로드가 2.4 GB를 넘는다. 기성 0.8B는 한국어에서 무작위 수준이었으므로 우리 데이터로 다시 학습하는 것이 사실상 필수다 |
| I4 | **칸 고르기도 Kev**가 한다 (2단계) | 사용자 결정. 칸별 확률이 곧 배치 점수의 "말과의 맞음"이 된다 |
| I5 | **남는 손도 AI가 채운다** — 엔진은 규칙(한 칸 한 가지, 비용, 금지, 행동 수)만 지키고 고르지 않는다 | 사용자 결정. 짚은 점: AI가 남는 손을 똑똑하게 쓸수록 적게 말해도 좋은 수가 나와 대본이 강해진다. 상태에 무엇을 넣느냐가 손잡이 — 나중에 대본 봇과 숙련 봇의 차로 잰다 |
| I6 | **두 단계로 묻는다** — 1단계 "무엇을" (칸 정보 없음), 2단계 "어디서" (뽑힌 일만, 칸 이름이 붙은 상태) | 부르는 횟수 2로 고정. 1단계 입력은 판 크기와 무관하게 같은 길이 |
| I7 | **1단계 상태는 JSON**, 플레이어가 화면에서 볼 수 있는 것만 | 아래 §2 |
| I8 | **배포**: 게임은 정적 호스팅, 모델은 Hugging Face Hub에서 받는다 | GitHub Pages는 사이트 1 GB·대역폭 월 100 GB(소프트)·git 파일 100 MB 한도, 그리고 주로 상업 목적인 사이트를 금한다 — 상업 배포 단계에서는 게임 호스팅도 옮긴다 |
| I9 | **라이선스**: Kev·Qwen3.5는 Apache-2.0 (배포 가능, 라이선스·고지문 동봉). SystemOne(CC-BY-NC)은 제외 | 게임 코드는 MIT. 이후 버전의 라이선스는 저작권자가 바꿀 수 있다 |

## 2. 1단계 상태 — 넣을 것과 뺄 것

| 갈래 | 항목 | 넣나 |
|---|---|---|
| 말을 알아듣는 데 필요한 형편 | 이번 사건, 율법파의 뜻, 지난 계시 | 넣음 |
| 규칙상 할 수 있는 것 | 지금 할 수 있는 일, 행동 수 | 넣음 |
| **상대(율법파) 정보 — 보이는 것만** | 이번 율법 카드, 뜻, 신도·마을·성벽·수도 내구도, 우리 선교·공격에 대한 대비(읽힘 방어) | 넣음 (사용자 지시) |
| 신만 하는 일 | 손에 든 기적, 계명, 예언, 이름 붙이기 — 엔진이 계시 글에서 따로 읽는다 (`parseMiracle` 등) | 뺌 |
| 전략 판단의 재료 | 승점, 선공, 읽힘 연속, 교리 칸, 다음 장 사건, 다음 장 율법 카드 | 뺌 |
| 플레이어가 응답할 몫 | 청원 (AI가 채우면 은총을 공짜로 얻는다) | 뺌 |
| 경계 | "모자란 것" — 넣으면 남는 손이 살림을 챙긴다 | **열림** — 난이도 손잡이로 제안 (쉬움·보통 넣음, 어려움 뺌) |
| 못 보는 정보 | 덱의 뒷순서, 안개 속 칸, 난이도로 가려진 뜻 | 뺌 |

## 4. 열린 것

| # | 열린 것 | 선택지 |
|---|---|---|
| O1 | **1단계 질문의 꼴** | ⓐ 일마다 "해야 하는가?" 예/아니오 12 + "금하는가?" 예/아니오 12 (24줄, 정답 붙이기가 가장 단순 — 석판 사례의 `forbid:` 정답을 쓴다, 둘 다 "예"인 모순은 규칙으로) · ⓑ 일마다 "하라 / 하지 마라 / 말하지 않음" 12 (같은 정보를 절반 줄로, 모순 없음 — 의견: 이것을 권함) · ⓒ 예/아니오 12 + 금지는 석판 규칙 (은유적 금지를 놓침). 어느 쪽이든 **"하라" 확률 순으로 행동 수만큼 채운다** — "가장 먼저 할 일"·"남는 손" 질문은 따로 두지 않는다. 계시의 성격은 4지선다 하나 |
| O2 | 명한 일과 채운 일을 가르는 **문턱** | 예: 확률 0.5 이상 = 계시가 명한 일, 그 아래 = 뜻을 헤아린 손. 확인 칩·판결·되풀이 판정·문장 틀이 이 구분을 쓴다 |
| O3 | 2단계에서 **채운 손의 칸** | Kev가 꼭 고른다 ("곳을 말하지 않음" 없음) / 기본값(D5)에 맡긴다 |
| O4 | "모자란 것"을 상태에 넣나 | §2 |
| O5 | 질문 글의 언어 | 영어 (Kev가 배운 말) / 한국어. 계시는 한국어 그대로 |
| O6 | 확신도가 낮을 때 | 석판으로 넘김 / 대사제가 "말씀이 흐릿하다" |

## 5. 2단계 — 어디서 (초안)

- 상태: 칸 이름이 붙은 사실 — 우리 수도·마을, 율법파 수도·마을·성벽, 성지, 율법파의 뜻("C4에 마을을 지으려 한다"), 붙인 이름.
- 질문: 뽑힌 일마다 "이 일을 어느 칸에서 하라는가?" — 선택지는 **그 일을 할 수 있는 칸만**, 글은 `C4: 평원`처럼 이름과 지형만. **수확량·활성도는 넣지 않는다** (값이 새지 않게 — Kev가 기름진 칸을 알아서 고르지 못하게).
- 석판에 남는 것: 정확한 지목(칸 이름 "E4", 붙인 이름, "E4 말고"), 수의 말("두 곳", "모두"), 활성도 낱말("기름진 곳", "쉬던 땅") — 글자 맞춤이라 규칙이 확실하다.
- 수의 말이 있으면 같은 칸 질문의 2순위까지 가져간다.

## 6. 해 보고 버린 것

| 안 | 버린 까닭 |
|---|---|
| 칸마다 관계 글을 붙인 선택지 ("E4: 숲 · 우리 수도 동쪽 2칸 · 율법파가 노리는 곳") | 닿는 칸이 늘수록 문맥이 길어진다 (사용자) |
| 지도 전체를 상태에 | 판이 커질수록 길어지고, 좌표로 공간을 추론해야 한다 — 0.8B가 약한 일 |
| 칸을 깊은 이진 트리로 고르기 | 지도를 봐야 하고, 틀림이 단계마다 곱해지고, 부르는 횟수가 늘어 Kev의 장점(한 번에 나란히)을 버린다. 얕은 문(gate)으로는 쓸 만하다 |
| 남는 손을 엔진이 채우기 | 사용자가 AI로 모든 행동력을 쓰기를 원함 |
| 장소를 고정 슬롯(기준·관계·방향·땅)으로 묻기 | 칸 고르기를 Kev에게 맡기기로 하면서 2단계 칸 명단 방식으로 바뀜 |

## 7. Kev의 입출력 (요약)

- 요청: `{ state, questions: { 이름: { type, instructions, criteria } } }`. `state`는 문자열이나 JSON (객체는 `키: 값` 줄로, 배열은 `- 항목` 줄로 편다).
- 질문 종류: `noul` (예/아니오, 답은 예의 확률) · `choice` (1~255 선택지 중 하나, 확률 분포·1순위·확신도) · `score` (순서 있는 등급, 기댓값 등급·분포·확신도).
- 질문끼리는 서로를 보지 않는다. 한 질문은 하나만 고른다 (여럿은 `noul`을 항목마다). 선택지 순서가 답을 바꿀 수 있다 (`/v1/systemone/permute`).
- 속: Qwen3.5 바탕에서는 질문마다 "상태 + 그 질문"을 한 줄로 보통 순서대로 돌리고 (`rows_of`), `<decide>` 자리와 각 `</opt>` 자리의 은닉 상태를 작은 판정 헤드(차원 → 256 두 행렬의 내적, 온도 보정)로 견준다. 특수 토큰은 Qwen의 예약 토큰을 빌린다 (`<|fim_prefix|>` 등).
- 코드: [github.com/jaredpalmer/kev](https://github.com/jaredpalmer/kev) — `kev/api.py`, `kev/model.py`, `kev/serve.py`.
