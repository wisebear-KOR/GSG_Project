# 정보 — 도메인 영역 (2026-10-06)

게임이 쓰는 모든 정보는 `js/game/domain/`에서 정의하고 만든다.
원본은 엔진의 `state` 하나다. 정보 객체는 그것을 읽기만 해서 주제별로 묶은 것이다.
화면(`main.js`·`board.js`), 해석기(`interpreter.js`), 엔진의 자원 셈은 정보를 `state`에서 직접 셈하지 않고 여기서 받는다.

## 2. 정보 객체

`gameInfo(state)` = `{ setup, turn, event, board, us, enemy, words, costs }`. 덩어리마다 함수가 따로 있어 화면은 필요한 것만 부른다.
둘 다 못 보는 것(덱의 뒷순서, 안개 속 칸의 내용, 난이도로 가려진 뜻, 주사위)은 처음부터 넣지 않는다.

| 덩어리 | 함수 | 담는 것 | 누가 보나 | 쓰는 곳 |
|---|---|---|---|---|
| `setup` 판 설정 | `setupInfo` | 크기·난이도·시드·두 번째 판, 열린 모듈 수, 은총, 율법 석판, 시련·승천·축복·오늘의 계시·도전장, 지난 판의 유적, 대사제, 신의 이름과 표장, 계시 글자 한도 | 플레이어만 | 부제, 계시 칸 글자 수, 장 머리 연출, 제단(표장·서원 칩·말 거두기), 칸 툴팁(석판), 프롬프트(신의 이름·유적·대사제) |

## 3. 누가 보나

정보 객체의 경로마다 `SEEN`에 적는다. 가장 긴 앞부분이 맞는 줄을 따르고, 표에 없는 경로는 플레이어만 본다.

| 값 | 뜻 |
|---|---|
| `priest` | 플레이어도 대사제도 |
| `player` | 플레이어만 |
| `byDifficulty` | 쉬움·보통은 대사제도, 어려움은 플레이어만 (모자란 것) |
| `afterReveal` | 공개된 뒤에만 둘 다 (이번 장 율법 카드) |

- 플레이어는 정보 객체를 모두 본다. 화면은 `view`를 거치지 않는다.
- 대사제의 눈은 `view(info, 'priest', {difficulty, revealed})`다. 해석기 1단계(무엇을 할지)에 넣을 상태다 ([INTERPRETER.md](INTERPRETER.md)).
- 전략 재료(승점·자원·교리·기적·계명·예언, 칸의 값)는 대사제에게 주지 않는다. 상대(율법파)의 정보는 준다.
- △ 표시는 아직 정하지 않은 것이다. 정할 때까지 플레이어만 본다: 장 번호·막(`turn`), 믿음의 표식, 지난 장에 한 일.
- 지금의 LLM 프롬프트(Gemma, `buildPrompt`)는 `gameInfo`에서 읽지만 `view`로 거르지 않는다. 옛 해석기의 글을 한 글자도 바꾸지 않기 위해서다. 걸러 쓰는 것은 Kev 해석기부터다.

## 4. 코드를 쓸 때

1. 화면·해석기는 보여 줄 정보를 `state`에서 직접 셈하지 않는다. 덩어리 함수를 부른다.
2. 정보 함수는 `state`를 읽기만 한다(`info.mjs`가 검사). 재생 중 보드(`makeView`로 만든 뷰)도 그대로 받는다.
   **원본 스냅숏(`{tiles, sides}`)은 `makeView`로 감싸서 넘긴다** — 설정이 없어 할 수 있는 일을 셈하다 멈춘다(실제로 `revealPerk`에서 겪었다).
3. 자원은 `Res` 하나로 다룬다.
4. 칸에 묶인 행동(`legalActions`, 행동 글, 명령 검사, 해결)은 엔진의 것이다. 칸 없이 일을 가리킬 때는 일의 종류(`kinds.js`)를 쓴다.
   뜻 하나를 행동 모양으로 펼 때는 `{ ...kindParts(kind), tile }`.
5. 상태를 바꾸는 일(신앙 내기, 기적, 고르기)은 행동 함수에 둔다. 정보 영역은 아무것도 바꾸지 않는다.
6. 이름 붙이기(`tileName`, `actionLabel`, `enemyLabel`)는 표시 함수가 한다. 정보 객체의 칸·뜻을 그대로 받는다.
7. 새 정보를 더하는 순서: `types.d.ts` → `info.js` → `seen.js`(누가 보나) → `tools/tests/info.mjs`(엔진과 같은가) → 이 문서의 표.
